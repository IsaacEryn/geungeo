# 근거(geungeo) — 대학 행정 근거 찾기 에이전트

업무 중 "무슨 규정이냐"와 새 업무 기안 때 필요한 근거 조항·절차·선행 요건을
시행일·출처와 함께 찾아 주고, 근거가 없으면 '근거 없음'이라고 답합니다.

- 데모 영상(4분 40초): https://youtu.be/6x8uYDlUyrE
- 바로 써 보기: https://geungeo-iota.vercel.app — 접근 코드가 필요합니다(심사용 코드는 제출 폼에 적었습니다)
- 정확도: 처음 보는 별도 문항 10문항 중 10문항 정답(2026. 11. 14. 1회 실행, 판정 이름까지 같은 것은 9문항). 개발 중 쓴 평가 28문항은 28/28이지만, 이 문항의 실패를 보며 고친 결과라 대표 수치로 쓰지 않습니다

## 실행 (5분)

필요: Node.js 22.13.1 이상(`.nvmrc`, 22.13.1과 24.7에서 확인), Liner API 키

평가 실행기(`npm run eval`)가 쓰는 vite와 수집기(`npm run collect`)는 22.12 이상을 요구합니다. 실제로 설치·빌드·테스트를 확인한 가장 낮은 버전인 22.13.1을 최소 버전으로 적었습니다.

```sh
npm install
cp .env.example .env    # .env의 LINER_API_KEY= 뒤에 발급받은 키를 넣습니다
npm run dev             # http://localhost:3000
```

운영 빌드로 띄우려면 `npm run build && npm start`를 씁니다(주소는 같습니다). 운영 빌드에는 아래 '화면' 절의 목 데이터 기능이 빠져 있습니다.

질문 하나에 답이 나오기까지 보통 30~40초가 걸리고, Liner API 비용은 질문당 약 $0.02입니다. 진행 중에는 화면에 단계별 상태가 표시됩니다.

설치 중 eslint 지원 종료 경고와 moderate 취약점 경고(개발용 의존성 minimatch)가 나오지만 실행에는 영향이 없습니다.

(선택) `npm run eval` — 평가 문항 28개를 돌려 통과율을 출력합니다(`.env`를 같은 방식으로 읽음). 키 없이 흐름만 보려면 `npm run eval -- --mock`(Liner를 부르지 않고 Search 고정 응답과 규칙 기반 대역으로 돕니다). 대역은 흐름 확인용이라 `--mock`의 통과율은 20%대(28문항 중 6개 안팎)로 낮게 나오는 것이 정상이며 품질 지표가 아닙니다. 결과는 `eval/runs/` 아래에 남습니다.

다른 문항 파일로 돌리려면 `npm run eval -- --questions <jsonl 경로>`를 씁니다(형식은 `eval/questions.jsonl`과 같고 저장소 밖 경로도 됩니다). 시행일 함정과 근거 없음 집계는 문항의 `trap`·`expected_verdict` 필드를 따르고, `summary.json`에는 경로 없이 파일 이름과 문항 수만 남습니다.

키는 서버 쪽에서만 읽고 브라우저로 보내지 않습니다. `.env`는 커밋되지 않습니다.

## 화면

웹 한 화면입니다. 질문을 적고 '근거 찾기'를 누릅니다. 학교(학칙)와 기준일은 접혀 있는 '검색 조건'에서 고르며, 접힌 상태에서도 요약 줄에 지금 값이 보입니다. 기준일은 오늘이 기본이고, 그날 시행 중인 조문으로 답합니다. 예시 질문은 네 개(진행 중인 업무·새로 시작하는 업무·시행 전·근거 없음)가 바로 보이고 '예시 2개 더 보기'로 두 개(진행 중인 업무)를 더 펼칠 수 있으며, 누르면 바로 찾습니다. 결과 아래에도 '다른 예시'가 있어 이어서 새 질문을 시작할 수 있습니다.

- 결론 한 단락과 판정(근거 있음/일부 근거/근거 없음), 기준일, 법령 데이터 수집일
- 근거 카드: 법령 이름·조항호목, 원문 인용, 시행일과 상태 배지(시행 중/시행 예정/입법예고), 근거 등급, 원문 링크, 출처 표기(학칙은 대학명 먼저)
- 새로 시작하는 업무를 묻는 질문이면 체크리스트(단계·기한·근거), 수집 뒤 바뀔 수 있는 것은 변경 신호, 근거가 없으면 찾아본 범위와 확인할 곳
- '처리 과정 보기'를 펼치면 Liner Router·Liner Search를 부른 지점, 검색어, 결과 hostname과 등급, 소요 시간, 토큰, 금액이 나옵니다

접근성은 WCAG 2.2 AA와 KWCAG 2.2를 기준으로 만들었습니다. 키보드만으로 모두 쓸 수 있고, 진행 상황은 화면 읽기 프로그램에 상태 메시지로 알리며, 상태 배지는 색과 함께 글자·아이콘으로 구분합니다.

개발 서버(`npm run dev`)에서는 파이프라인 없이 목 데이터로 화면을 볼 수 있습니다. 주소 끝에 `?demo=E22`처럼 예시 ID(E09·E19·E22·E28·E03·E06)를 붙이면 그 예시가 바로 뜨고, `?mock=1`이면 예시 버튼이 목 데이터로 답합니다. 목 데이터 화면에는 안내 띠가 붙고, 배포 빌드(`npm run build`)에서는 목 데이터로 답하지 않고 목 데이터 파일도 묶음에 들어가지 않습니다.

## Liner API를 쓰는 곳

- Liner Search(`search/web`, `include_knowledge: false`): 저장소에 담아 둔 법령·학칙 조문만으로는 알 수 없는 교육부 공고·보도자료·입법예고 같은 최근 변경 신호
- Liner Router(기본 모델 `liner-mark-1.3`): 질문 분석(장면 분류·검색어, `LINER_MODEL_ANALYZE`), 조문·웹 근거 대조와 답 작성·근거 없음 판정(`LINER_MODEL_ANSWER`), 평가 보조 채점(`LINER_MODEL_JUDGE`)
- 질문 분석의 추론 강도는 `LINER_REASONING_ANALYZE`(none|low|medium|high|max, 비우면 low)로 바꿉니다. 질문 분석에만 적용되며, Liner 기본값으로 되돌리려면 `LINER_REASONING_ANALYZE=medium`으로 둡니다
- 답변 단계(조문 대조·판정)의 추론 강도는 `LINER_REASONING_ANSWER`(none|low|medium|high|max)로 따로 바꿉니다. 비우면 값을 보내지 않아 Liner 기본값(medium)으로 답합니다. `low`로 두면 답이 빨라지지만 평가에서 판정이 흔들려 기본값으로 쓰지 않습니다
- 두 추론 강도 변수에 위 다섯 값이 아닌 값(오타 등)을 주면 경고 없이 무시하고 비운 것과 같게 처리합니다. 질문 분석은 low로, 답변 단계는 값을 보내지 않습니다. 평가 실행기의 `summary.json`에는 실제로 보낸 값과 환경변수 원문, 실행한 커밋 해시가 함께 남습니다
- (선택) 단계별 값을 다른 라우터(`liner-gpt-router`·`liner-claude-router`)로 바꾸면 같은 흐름으로 실행됩니다. 평가 28문항에서 답변 단계 모델만 바꿔 돌린 결과는 `liner-mark-1.3` 28/28, `liner-claude-router` 27/28, `liner-gpt-router` 27/28이었고, 그래서 기본값을 `liner-mark-1.3`으로 두었습니다. 문항마다 한 번씩 돌린 값이고, 이 28문항의 실패를 보며 고친 뒤 같은 문항으로 잰 것이라 처음 보는 질문에서도 같은 통과율이 나온다는 뜻은 아닙니다

## 데이터

- `data/`: 법제처 국가법령정보센터에서 수집한 법령·행정규칙 조문(수집일은 `data/manifest.json`). 형식 예시는 `data/examples/`
- 출처 표기는 `NOTICE.md`. 학칙은 대학명을 먼저 적습니다
- 학칙은 시연·평가에 쓰는 조·항만 `data/rules/`에 담았습니다(서울대학교·부산대학교·한국방송통신대학교·경북대학교·서울과학기술대학교·대구교육대학교·대구사이버대학교, 출처는 `NOTICE.md`). 대구사이버대학교 학칙은 법제처 국가법령정보센터에 없어 학교 규정 웹사이트의 공개본을 옮겨 적었습니다. 실행 중에는 법제처 국가법령정보센터도 학교 웹사이트도 부르지 않습니다. 필요한 키는 Liner API 키 하나입니다
- 교육부 공고·안내 가운데 평가 문항에 쓰는 것은 `data/notices.json`에 제목·URL·게시일과 원문에서 확인한 수치만 담았습니다. 원문을 확인하지 못한 항목은 '원문 확인 필요'로 표시했습니다
- 데이터 갱신은 개발자용 `npm run collect -- --rules-out data/rules`(`scripts/collect/`, law.go.kr 공개 화면에서 받음). 심사 실행에는 필요 없습니다

## 평가 메모

- 평가 문항 E24의 근거 표기 '안 제2조제7항 단서'는 보도자료 표기를 따른 것이고, 개정령안 본문은 제8항 신설입니다. 채점에는 영향이 없습니다.
- 기준선 재채점(`scripts/eval/rescore.mjs`)은 결론(summary)만 보고, 새 실행은 결론·체크리스트·확인 사항을 모두 봅니다. 기준선 쪽이 조금 불리합니다.

## 개발자용

```sh
npm run lint
npm run typecheck
npm test          # vitest
npm run build
```

- `.npmrc`의 `legacy-peer-deps=true`를 지우면 `npm ci`가 실패합니다(잠금 파일이 이 설정에 맞춰 만들어져 있음)
- 커밋 전 비밀 검사: 저장소를 받은 뒤 `git config core.hooksPath .githooks` 한 번. 훅이 `gitleaks git --staged --redact`를 돌리고, gitleaks가 없으면 커밋을 막습니다
- 구조: 화면(`app/`, `components/`, `messages/`)은 `lib/pipeline/types.ts`의 타입만 압니다. 파이프라인은 `data/`를 `lib/cache/load.ts`를 거쳐서만 읽습니다

## 배포(선택)

로컬 실행에는 필요 없습니다. 외부에 주소를 열 때(예: Vercel) 아래 환경변수를 배포 쪽에만 넣습니다. 비어 있으면 각 기능이 꺼지고 로컬과 똑같이 동작합니다.

- `ACCESS_CODE`: 넣으면 질문 화면 앞에 접근 코드를 처음 한 번 넣는 화면이 나오고, 코드가 맞는 요청만 질문을 받습니다. 맞은 코드는 그 브라우저 탭에만 기억하므로 탭을 닫을 때까지 다시 묻지 않습니다. 주소 끝에 `#code=코드`를 붙여 열면 입력 화면 없이 바로 질문 화면이 나오고, 코드는 읽자마자 주소창에서 지웁니다(`#` 뒤는 서버로 가지 않아 접속 기록에 남지 않습니다).
- `DAILY_QUESTION_LIMIT`·`BUDGET_START_DATE`·`BUDGET_START_USD`: 셋이 모두 있을 때 하루 질문 상한이 켜집니다. 질문을 받기 전 Liner 사용량 조회(`GET /credits/usage`, 무료)로 시작일 이후 쓴 금액을 보고, 시작일(한국 시간)부터 오늘까지 일수 × 하루 상한 × 질문당 단가를 넘으면 그날은 더 받지 않습니다. `BUDGET_START_USD`에는 시작하는 날 열기 직전의 사용량 조회 합계(`summary.credits_usd`)를 넣습니다. 조회가 실패하면 막지 않고 통과시킵니다. 사용량 조회는 최근 30일 합계라 30일 넘게 운영할 때는 시작일과 시작 금액을 다시 잡습니다.
- `QUESTION_COST_USD`: 질문당 단가(비우면 0.02달러).
- `RATE_LIMIT_PER_MIN`: 같은 IP에서 1분에 받을 요청 수. 서버 인스턴스마다 따로 세는 보조 수단입니다.

`/api/ask`의 최대 실행 시간은 120초로 두었습니다. 접근 코드 화면을 보일지는 빌드할 때 정해지므로, 변수를 바꾼 뒤에는 다시 배포합니다.

## 한계

법률 자문이 아닙니다. 수집일 이후 개정은 변경 신호로만 알려 줍니다.

근거 카드가 이웃 항·호 번호를 달거나 여러 호를 한 카드에 묶어 보여 줄 때가 있습니다. 결과를 문서에 옮기기 전에 카드의 원문 링크로 조·항·호를 확인해 주세요.

학칙은 일곱 학교의 일부 조·항만 담았습니다. 서울대학교·부산대학교는 평가에 쓰는 조만, 경북대학교·서울과학기술대학교·대구교육대학교·대구사이버대학교는 휴학·복학, 재학연한, 다른 대학 학점 인정, 성적, 졸업 학점, 장학금·등록금 감면, 등록금심의위원회, 학칙 개정 절차 가운데 10개 조를 담았습니다. 담지 않은 조를 묻는 질문에는 '학칙 확인 필요'로 답합니다. 한국방송통신대학교는 2027. 3. 1. 시행 예정인 부칙(학과 명칭 변경)만 담았고, 2026. 11. 기준 시행 중인 판(제1309호)의 본문은 담지 않았습니다.
